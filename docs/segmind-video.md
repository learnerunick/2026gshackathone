# Segmind 영상 연동

2026-09-21. Segmind Pro 구독으로 20~30초 영상을 만드는 수동 화면과 AI 연속 제작 경로를 제공한다. 사용자는 기존 한도 안에서 자동 영상 제작도 승인했다. 구독 가입·API 키 인증·실제 영상 제출은 각각 구분한다. 실제 생성은 사용자가 시작한 영상 포함 자동 실행 또는 수동 영상 생성 요청에서 이루어진다.

## 수동 영상 제작

1. `python3 apps/backend/server.py serve`로 서버를 실행한다.
2. http://127.0.0.1:8765/video 또는 스튜디오 상단 **영상 제작**으로 이동한다.
3. https://platform.segmind.com/ 에서 API 키를 발급하고 화면의 **Segmind API 연결**에 입력한다. 키를 채팅·Git·스크린샷에 남기지 않는다.
4. **저장 · 연결 확인**은 계정 인증 GET 요청만 수행한다. 성공하면 키를 `.runtime/segmind-api-key`에 권한 0600으로 저장한다. API 응답이나 생성 기록에 키를 반환하지 않는다. 서버 환경변수 `SEGMIND_API_KEY`도 지원하며 저장된 로컬 키가 우선한다. `.env` 파일을 자동으로 읽지는 않는다.
5. 페르소나를 선택한다. 등록된 외형 사진이 있으면 해당 버전의 사진을 필수 첫 인물 참조로 사용하며 사진 없는 시안 생성은 차단한다. PNG·JPEG·WebP(10MB 이하)를 추가 업로드하면 장소·소품 등의 보조 참조로 사용하며 인물 기준을 교체하지 않는다. 등록된 사진이 없는 페르소나만 업로드·기존 이미지 콘텐츠를 기준으로 선택하거나 **기준 이미지 없이 시안 생성**을 명시적으로 선택할 수 있다. 사진 없는 시안은 기존 페르소나와 외형이 달라질 수 있으며 결과에 검토 메모를 남긴다. 업로드는 로컬 저장만 하며 페르소나 원본을 변경하지 않는다.
6. 제목·스토리보드·게시 문안과 길이·화질을 확인한 뒤 **영상 생성**을 누른다. 참조 이미지 업로드와 영상 생성에 Segmind 계정을 사용한다.
7. 완료한 영상은 검토 대기 콘텐츠로 등록한다. **영상 검토**에서 재생·문안 수정·버전별 승인·ZIP 다운로드를 할 수 있다. Instagram 전송은 이 연동의 범위가 아니다.

## 영상 제작 참고 MD

대시보드 **콘텐츠 제작 → AI 자동 제작 → 영상 제작 참고 MD → MD 파일 선택 → MD 등록**으로 공통 지침을 등록한다. 파일 내용은 일반 텍스트로 미리보기하며 HTML·스크립트·외부 링크를 실행하거나 가져오지 않는다.

- UTF-8 `.md`, 파일당 64KB·12,000자 이하, 최대 10개. 자동 적용한 파일 내용 합계는 12,000자 이하다.
- 새 파일은 자동 적용된다. 같은 파일명으로 재등록하면 새 버전으로 교체하며 기존 적용 여부는 유지한다. 화면에서 적용 켜기·끄기와 삭제를 지원한다.
- 프로젝트 공통 지침으로 모든 페르소나의 **새 수동·자동 영상 작업**에 반영한다. 자동 제작은 콘텐츠 순환을 시작할 때 활성 MD를 고정해 `job.input_json.video_guides`로 AI 기획·스토리보드·검수 단계에 전달한다. 최종 영상 요청에도 같은 버전을 넣는다. 변경한 MD는 다음 콘텐츠 순환부터 적용하며 이미지 중심 실행에는 넣지 않는다. 직접 영상 제작은 접수 시 활성 지침을 사용한다. 등록만으로 실행을 시작하지 않는다.
- **MD 관여도 기본값은 낮음**이다. AI는 이번 이야기를 먼저 기획하고 모든 MD를 합쳐 분위기 요소를 최대 1~2개만 선택적으로 참고한다. 맞지 않으면 생략하며 예시의 주제·도입·소품·장면 순서·컷 수·결말을 그대로 반복하지 않는다. 영상 프롬프트에도 스토리보드를 먼저 넣고 MD를 보조 참고로 구분한다. 페르소나 정체성·사실 확인·가상 인물 표시·승인 기준은 유지한다. MD 항목의 전부 반영을 품질 합격 조건으로 삼지 않는다. 이는 기획·프롬프트 정책이며 모델의 수치 가중치나 실제 유사도 보장이 아니다.
- SQLite `video_guides`에 파일명·본문·버전·해시·적용 여부를 저장한다. 새 영상 접수 시 적용한 파일 전체와 최종 `generation_prompt`를 `video_jobs.input_json`에 함께 저장한다. 제작 기록의 **적용한 MD**에서 당시 본문을 확인한다.
- 자동 제작의 MD와 참고 정책은 `production_cycle_video_guides`에 콘텐츠별로 고정한다. AI 단계에는 `video_guide_policy`, 영상 작업에는 `guide_policy`로 정책 버전과 내용을 함께 남긴다. 등록 후 지침을 바꾸거나 삭제해도 이미 시작한 콘텐츠와 대기·진행·완료한 영상의 입력은 바뀌지 않는다. 재시작과 같은 요청 키 재전송도 원래 입력을 사용한다.
- 수동 생성은 화면에 보인 MD 버전을 함께 확인한다. 그 사이 변경됐다면 409를 반환해 새 목록 확인 후 다시 요청하도록 한다. 등록·적용 변경도 `base_version`으로 오래된 변경을 막는다.

## 설정과 비용

`config/video.json`에서 로컬 운영 한도를 설정한다. 기본 모델은 `seedance-2.5`, 세로 9:16이다. 수동 영상의 기본값은 30초·720p이며 **AI 자동 제작은 20초·480p**다. 이 MVP는 20~30초 및 480p/720p를 지원한다. 음성 생성은 포함하며 참조 영상 입력은 제공하지 않는다.

콘텐츠 제작 → AI 자동 제작 → 자동 영상 설정에서 길이·해상도를 선택한다. **영상 기본값 저장**은 다음 실행에 사용할 값을 SQLite에 저장하며 생성을 시작하지 않는다. 저장하지 않고 시작하면 해당 실행에만 선택값을 사용한다. 기본값은 `config/overnight.json`의 `video.duration/resolution`이며 저장된 `generation.auto_video`가 우선한다. 실행 시작 때 `run.settings.video`에 고정하고 각 단계의 `video_settings`로 전달한다. 기획·스토리보드는 이 길이에 맞게 작성하고 실제 Segmind 요청도 같은 값을 사용한다. 실행 중 기본값을 변경해도 해당 실행과 접수된 영상 요청은 바뀌지 않는다. 옵션 도입 전 실행은 기존 공통 영상 설정을 유지한다.

- 공개 요금 기준 30초 720p: 약 $7.17, 480p: 약 $3.20. 정확한 청구 금액은 Segmind의 최종 사용량을 확인한다.
- 자동 제작 기본값인 20초 480p는 약 $2.13다. 길이·해상도를 바꾸어도 비용·대기 한도는 유지한다.
- 기본 동시 대기·진행·확인 필요 작업 최대 2건.
- 한 편 예상 비용 상한 $8, UTC 날짜 기준 하루 예상 비용 합계 $15. 이 값은 계정 전체의 실제 청구 상한이 아니라 Boca에서 생성 요청을 제한하는 보수적 추정치다.
- 실패하거나 응답이 유실된 작업의 추정치도 당일 합계에 유지한다. 실제 환불 여부와 계정 내 다른 사용량을 추정하지 않는다.
- 유료 생성 POST의 자동 재시도는 0회. 참조 업로드의 일시 오류와 기존 작업 조회·다운로드 오류는 기본 10·20·40·80초 간격으로 복구하며, 연속 오류 5회면 자동 시도를 멈춘다. 재시도 시각·횟수는 DB에 저장되어 서버 재시작 후에도 유지된다.
- 가격 기준일 2026-09-21. 요금이 바뀌면 백엔드와 화면의 초당 추정 단가도 함께 갱신한다.

추정 단가는 구현에 저장된 2026-09-21 기준 값이다. 자동·수동 요청은 같은 video_jobs 예산·대기 집계를 사용한다. `config/overnight.json`의 기존 `paid_api_allowed: false`를 다른 유료 공급자 호출이나 추가 결제 허용으로 바꾸지 않는다. 이번에 명시적으로 승인된 Segmind 자동 제작만 기존 한도 안에서 실행한다.

## AI 콘텐츠 자동 생성과 연결

대시보드 콘텐츠 제작 → 자동 생성에서 미디어 형식을 선택한다. images는 이미지 전용, mixed는 이야기에 맞게 이미지 또는 영상, video_only는 영상만 제작한다. 기존 API의 video는 영상 우선으로 유지한다. 현재 UI 기본값은 사용자가 승인한 mixed이며 실행 시작 후 그 run의 형식과 페르소나 버전은 고정된다.

1. Codex heartbeat가 일상 기획 → 스토리보드 → 문안을 작성한다. 각 단계의 decision_summary에 짧은 공개 선택 근거를 남긴다. 서버만 켜 두어도 AI가 기획하는 구조는 아니다.
2. images 단계에서 `python3 apps/backend/server.py worker-video CYCLE TOKEN` 또는 `POST /api/worker/video`를 호출한다. 입력은 cycle_id와 lease_token이며 기획·문안·참조 인물은 해당 실행에서 가져온다. 사람이 영상 폼에 다시 쓰지 않아도 된다.
3. storyboard.video_prompt가 있으면 영상 지시문으로 사용하고, 없으면 storyboard.cards를 전달한다. 제목은 planning.title, 문안은 copy.caption이며 run.persona_id와 persona_version을 유지한다. 엄마 기준 이미지는 버전별 불변 참조를 사용한다. 별도 요청 키는 순환 ID에서 만들어 중복 제출을 방지한다.
4. 영상만(`video_only`)은 이미지로 대체하지 않는다. 기획은 `content_format: video`, 미디어 완료·등록은 MP4만 허용한다. API 키·기준 이미지·비용·대기 한도 미충족이면 `{status: blocked, fallback: null, reason: ...}`을 반환하고 실행을 확인 대기로 저장한다. 조건 해결 후 사용자가 재개하면 같은 미디어 단계에서 이어간다. mixed와 기존 video는 API 키 연결·기준 이미지·비용·대기 한도가 맞지 않으면 `{status: skipped, fallback: images, reason: ...}`를 반환하고 media.video_skipped 이벤트에 사유를 남긴다. Codex는 이미지 피드 제작을 계속한다. 한도를 늘리거나 참조 없는 인물 영상을 자동으로 제출하지 않는다.
5. 요청이 접수되면 서버의 비동기 영상 작업자가 생성·조회·다운로드를 진행한다. 미디어 파일을 저장하면 images 단계만 완료하고 AI 품질 검수로 넘긴다. 자동 영상 경로에서 콘텐츠 import는 quality 이후 Codex의 register 단계에서만 수행한다. 사람이 승인하기 전 게시하지 않는다.

접수 전 조건 미충족과 제출 후 불확실 상태를 혼동하지 않는다. 이미 제출한 요청의 결과가 불확실하면 같은 유료 요청을 다시 보내거나 임의로 성공 처리하지 않는다. 기존 외부 작업 ID로 결과를 확인한다. 사용자가 실행을 중지했거나 기한이 지났으면 새 제출을 막고 이미 반환되는 파일·외부 결과는 보존한다.

기존 실행은 최신 인계에서 사용자가 중지한 상태다. 설정·문서를 변경하거나 서버를 재시작해도 이를 다시 시작하지 않는다. 사용자가 대시보드의 자동 생성 버튼으로 새 실행을 시작해야 한다.

## 작업과 복구

SQLite `video_jobs`에는 입력 스냅샷, 원본 콘텐츠/페르소나 버전, 참조 이미지 해시, 요청 키, 외부 작업 ID, 결과 URL·비용 지표, 단계와 오류를 저장한다. 이미지를 파일 해시로 복사해 후속 편집과 분리한다.

등록된 인물 사진은 수동·자동 영상 모두 `reference_images`의 첫 항목이며, `identity_reference`에 파일·해시·페르소나 버전을 기록한다. 같은 버전의 연령·외형·메이크업 지침도 스냅샷과 생성 프롬프트에 포함한다. 다른 참조 사진의 얼굴로 인물을 대체하지 않도록 명시한다. 접수 후 프로필을 변경하거나 서버를 재시작해도 해당 작업의 참조는 유지한다. 이는 입력 고정이며 생성 결과의 얼굴 일관성은 실제 영상에서 검수한다.

`queued → preparing → submitting → running → downloading → completed`

- 요청 키 재전송은 기존 작업을 반환한다. 다른 내용에 같은 키를 재사용하면 409다.
- 서버 실행 시 단일 작업자 파일 잠금을 획득한다. 다른 서버 프로세스와 같은 DB를 사용할 때 유료 요청을 중복 전송하지 않는다.
- `submitting` 이전에 단계를 커밋한다. 응답 유실 또는 제출 중 재시작은 `uncertain`으로 남기며 생성 POST를 반복하지 않는다.
- 외부 ID를 이미 받았다면 재시작 후 같은 ID를 조회한다. 조회 실패가 반복되거나 45분을 넘기면 `attention`에서 확인을 기다린다.
- ‘조회 재개’는 새 45분 관찰 구간을 시작한다. 이미 결과 URL을 받았다면 다운로드 단계부터 이어가고, 원자적으로 저장된 로컬 MP4가 있으면 만료된 외부 조회를 거치지 않는다. 다운로드 주소가 401/403/404/410을 반환하면 같은 외부 ID로 결과 주소만 갱신한다. 주소 갱신으로 연속 오류 횟수를 초기화하지 않아 무한 반복을 막는다.
- MP4 헤더뿐 아니라 응답 Content-Length와 실제 다운로드 크기를 비교한다. 중간 파일은 실패 시 제거하며 검증한 파일만 최종 경로로 이동한다.
- 영상 저장 후 제작 단계 반영이 실패해도 `completed`와 파일을 유지한다. `sync_pending`·`sync_errors`·`sync_error`에 반영 상태를 따로 저장하고 같은 결과 반영만 최대 5회 시도한다. 한도 도달 후 `/video`의 **저장된 결과 반영 재개**로 복구한다. 생성 요청·다운로드를 반복하지 않는다.
- 오류·다음 복구 시각·한도 도달은 단계 로그와 영상 화면에 표시한다. 현재 영상의 실제 완료 파일과 외부 ID를 확인하면 해당 영상의 불확실성 때문에 차단된 실행만 자동으로 다음 단계로 이어간다. 공급자가 기존 작업의 실패를 확정한 경우에는 실패 기록을 남기고 다음 콘텐츠를 준비한다. 상태 반영과 차단 해제는 같은 DB 트랜잭션에서 처리한다. 사용자의 일시정지·중지, 다른 차단 사유, 3회 연속 실패 제한은 자동 해제하지 않는다. 조회 재시도 한도 자체를 늘리거나 결과 미확인 유료 요청을 다시 제출하지 않는다.
- 교체 서버의 영상 작업자는 기존 서버가 보유한 잠금이 해제될 때까지 기다린다. 인계 후 기존 외부 ID부터 조회하므로 두 서버가 중복 제출하지 않는다.
- 화면의 **기존 작업 결과 조회 재개**는 생성하지 않고 기존 작업만 조회한다. ID가 유실된 경우 Segmind 생성 기록에서 동일 요청의 ID를 확인해 입력한다.
- 반환 결과의 URL은 인증 키 없이 다운로드하며 HTTPS·공개 주소·MP4·250MB 한도를 검사한다. 완료 결과는 즉시 로컬에 저장한다. Segmind 문서상 조회 결과는 1시간 후 만료될 수 있다.
- 수동 결과는 원본 카드형 콘텐츠와 별개의 새 영상 콘텐츠로 검토 대기에 등록한다. 자동 결과는 해당 제작 순환의 미디어 결과로 저장하고 Codex의 품질 검수·등록을 기다린다. 두 경로 모두 원본의 사람 수정·승인을 늦은 응답으로 덮어쓰지 않는다. 영상 문안을 수정하면 기존 승인도 무효화된다.
- 동일한 입력을 다시 보내는 버튼 클릭은 중복 요청으로 처리한다. 새 시안이 필요하면 입력 내용을 변경해 새 요청을 만든다.

## HTTP 계약

변경 요청에는 기존 `X-BOCA-Token`이 필요하다.

| 경로 | 역할 |
|---|---|
| GET /api/video | 비밀값을 제외한 연결 상태·설정·최근 작업 50건 |
| POST /api/video/connect | api_key(선택): 저장된 키 또는 환경변수로 읽기 전용 인증 확인 |
| POST /api/video/reference | data: 이미지의 base64 문자열. 로컬 저장만 수행하고 media 파일명을 반환 |
| POST /api/video/guides | filename, content(UTF-8 문자열), base_version(새 파일 0): 등록/동일 파일명 교체 |
| POST /api/video/guides/:id | base_version, enabled: 자동 적용 여부 변경 |
| POST /api/video/guides/:id/delete | base_version: 목록에서 삭제, 기존 작업의 지침 유지 |
| POST /api/video/jobs | request_key, accept_estimated_cost, persona_id, persona_version, title, storyboard, caption, duration, resolution, source_content_id/source_version, reference_media, text_only, guide_versions(활성 파일 id→version 매핑, 모두 선택) |
| POST /api/video/jobs/:id/resume | external_id(저장 ID가 없을 때): 기존 작업 결과 조회·다운로드 재개. sync_pending인 queued/running/downloading/completed이면 현재 영상 상태·저장 결과의 단계 반영만 재개 |
| POST /api/worker/video | cycle_id, lease_token: 해당 자동 제작 순환의 AI 입력으로 영상 요청. 미디어 단계 소유권과 실행 상태 검증 |
| GET /api/runs/:id/artifacts | 자동 제작에 연결된 상세 로그 파일·단계 결과 목록 |
| GET /api/runs/:id/logs?format=log | 읽기 쉬운 로그 다운로드. format=jsonl도 지원 |
| GET /api/runs/:id/stages/:cycle/images | 영상 입력·현재 결과·외부 ID·시도·체크포인트·공개 요약 조회 |

이미지·영상 제작 API 키와 Instagram 인증은 서로 별개다. API 키 인증 성공은 모델 사용 권한, 참조 이미지 허용 여부, 생성 성공을 보증하지 않는다. 실사형 가상 인물의 허용 여부와 실제 품질은 첫 실제 생성에서 확인해야 한다.

자동 영상의 상태·외부 ID·실패 이유는 `.runtime/production/<run_id>/events.log`, events.jsonl과 cycles/<cycle_id>/images.json에도 기록한다. 파일은 DB 커밋 후 원자적으로 교체하므로 `tail -F`로 추적한다. 입력·출력·공개 선택 근거는 보존하고 API 키·소유권 토큰·내부 사고 과정은 제외한다.

### 2026-09-21 오류 복구 검증

전체 Python 218개와 UI 로직 11개 통과. 재시도 시각의 재시작 보존, 연속 오류 한도, 제출 응답 유실 시 중복 방지, 참조 업로드 재시도, 만료 다운로드 주소의 제한된 갱신, 부분 다운로드 거절, 완료 파일의 단계 반영 재시도, 차단 후 같은 콘텐츠의 품질 검수 재개, 사용자가 중지한 작업의 늦은 파일 보관, 서버 간 작업자 잠금 인계를 테스트 대역으로 확인했다. 복구 UI는 브라우저의 가상 응답으로 검증했으며 유료 생성 요청은 추가하지 않았다.

배포는 기존 AI 총괄이 종료된 후 영상 작업자 잠금을 새 8765 서버로 인계했다. 실제 영상·외부 작업 ID를 유지했고 SQLite quick_check가 정상이다. 현재 run의 별도 차단 사유는 영상 생성 오류가 아니라 품질 검수 런타임의 음성 입력 미지원이며, 기존 영상의 오디오 검수가 필요하다.
