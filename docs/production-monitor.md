# 제작 현황 화면

`/#production`은 저장된 현재/마지막 실행을 읽는 전용 화면이다. 사이드바 ‘제작 현황’ 또는 active run이 있을 때 상단 상태 버튼으로 연다. 화면 조회만으로 작업을 시작하거나 소유권을 획득하지 않는다.

## 표시와 갱신

- 예약, 작업자 연결 대기, 실제 단계 진행, 응답 확인 필요, 일시정지, 오류 확인, 종료를 구분한다.
- 상단 버튼은 현재 단계와 완료/목표 개수를 표시한다. stopped/completed이면 숨기며 마지막 실행 기록은 상세 화면에 남는다.
- 실행에 고정된 페르소나·버전과 전문가 구성을 표시한다. 현재 화면의 선택 페르소나가 실행 대상을 바꾸지는 않는다.
- 현재 콘텐츠의 7단계 흐름, 실제 담당자, 등록 개수, 일정, 실패 사유, 최근 로그, 단계별 결과·체크포인트·이미지·영상과 원본 LOG/JSONL 링크를 연결한다.
- 종료 시각을 비우면 ‘시간 제한 없음’과 현재 목표 개수에 따른 종료 조건을 표시한다. 단계 결과는 완료 시 저장되며 종료 시각까지 보류하지 않는다.
- 일시정지·재개·중지는 기존 API를 사용한다. 알려진 불확실 작업 및 종료 시각 이후 재개는 비활성화하고, 서버의 소유권·복구 검증도 그대로 유지한다.
- 5초마다 상태를 조회하며 상단 DOM을 본문과 독립 갱신한다. 미저장 문안을 덮어쓰거나 영상 플레이어를 다시 만들지 않는다. 상세 화면 복귀 시에도 최신 정보를 요청한다.
- 상태 및 상세 기록 요청은 8초 제한을 둔다. 상태 연결이 끊기면 마지막 확인 정보라는 안내를 표시하고 연결 복구 후 자동 갱신한다. 상세 기록만 조회 실패하면 그 기록 영역에 오류를 표시한다.
- 단계 결과 창도 열린 동안 5초마다 해당 실행·콘텐츠·단계를 조회한다. 실제 배정의 현재 상태, 최근 작업 로그 6건, 결과·인계 요약을 갱신한다. 배정 상태 변경 시각과 총괄 연결 확인 시각은 구분하며 연결 신호를 전문가의 작업 완료 증거로 취급하지 않는다.
- 단계 창을 닫거나 다른 창으로 이동하면 조회를 취소한다. 늦게 도착한 응답은 무시하고, 오류 중에는 마지막 결과를 유지한다. 영상 재생 중에는 결과 영역 교체를 보류하면서 상태·로그만 갱신한다.

## 구현

`apps/dashboard/index.html`의 상단 버튼, `app.js`의 renderProductionStatus / productionMonitorState / renderProductionMonitor, `style.css`의 해당 스타일을 사용한다. 서버의 정적 파일 제공 경로를 유지하기 위해 기존 자산에 통합했다. 백엔드·실행 스케줄·DB 계약은 변경하지 않는다.

## 검증

격리 서버 8785와 공개 Store API로 명시적인 합성 작업을 만들었다. 운영 실행·실제 전문가·유료 공급자는 사용하지 않았다.

- active run 버튼 → 별도 경로 이동, 현재 전문가·문안 체크포인트 열기, LOG/JSONL 링크.
- 작업/일시정지/확인 필요/연결 실패·복구/예약 상태와 3건 완료 후 버튼 숨김.
- 검수 문안이 미저장 상태여도 topbar 갱신, 이동 취소 시 기존 문안 보존.
- 영상 재생 중 topbar 갱신 후 동일 video DOM 및 재생 위치 유지.
- 상세 화면 재개 제어, 불확실 작업 재개 비활성, 다음 단계 변경 반영.
- 1440px 데스크톱, 1024px, 390px, 320px 가로 넘침 검사.
- `node --check apps/dashboard/app.js` 통과. 기존 자동화 테스트 25개 통과. backend를 변경하지 않아 직전 전체 167개 로직 검증을 다시 실행하지 않았다.

스크린샷은 `output/playwright/monitor-*.png`에 보존한다. 연결 실패 검증에서 의도적으로 /api/state 네트워크 오류를 발생시켰으며, 실제 유료 생성·SNS 게시는 호출하지 않았다.
