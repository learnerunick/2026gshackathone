# 콘텐츠 제작 전문가 팀

현재 자동 제작은 AI 품질 검수를 제외한 **6단계**다. `job.input_json.ai_quality_review_enabled:false`이면 품질 검수자를 배정하지 않는다. 이 실행 정책이 기존 동결 역할의 검수 통과 요구보다 우선한다. 기존 미디어로 register를 진행하며, `review_handoff.notes`를 사람의 검수 메모로 전달한다. 청취 불가 등 미확인 사항은 기록하되 재생성이나 전체 제작 중단의 이유로 삼지 않는다. 아래 품질 검수 역할과 절차는 검수가 활성화된 과거 실행의 호환을 위해 남겨둔다. 사람의 버전별 게시 승인은 유지한다.

AI 자동 제작은 **제작 총괄 + 단계별 전문 서브에이전트**로 실행한다. 역할 설정은 `config/specialists.json`에 저장하고 신규 run 시작 시 버전과 지침을 고정한다. 이전 run의 설정을 임의로 변경하거나 기존 중지 실행을 재개하지 않는다.

| 단계 | 전문 역할 | 산출물 |
|---|---|---|
| GS 소재 웹 탐색 | GS 소재 리서처 | 공식 출처·본문 근거·유효기간·검색/제외 기록 |
| 일상 기획 | 라이프스타일 기획자 | 주제, 중복 확인, 소재 연결, 미디어 형식 |
| 장면 구성 | 스토리보드 디렉터 | 가변 길이 장면·이미지 지시문·영상 연출 |
| 문안 | 페르소나 카피라이터 | 캐릭터 말투의 문안·해시태그·가상 인물 표시 |
| 이미지·영상 | 비주얼 프로듀서 | 실제 이미지 파일 또는 Segmind 제작 제안 |
| 피드 등록 준비 | 피드 패키징 에디터 | 정확한 콘텐츠·인물 버전의 manifest |

총괄은 단계 소유권, 담당자 배정, 결과 검증·등록, 실패·재시도·중단 복구와 한도를 관리한다. 품질 검수자를 해당 콘텐츠의 제작 담당자와 분리한다. AI 검수 후 사람의 정확한 버전 승인은 별도다.

## 영상의 필수 구성

새 영상 요청은 한국어 보이스와 큰 자막을 반드시 포함한다. 스토리보드·카피 담당자가 시간별 `video_narration`을 넘기고, 비주얼 프로듀서는 보이스 연출과 서버 자막 합성을 연결한다. 독립 검수자는 실제 파일을 보고 들어 `video_checks`를 기록한다. [자막·보이스 계약](video-delivery.md)을 따른다. 기존 실행에 고정된 역할 버전을 덮어쓰지 않으며 새 역할 팩은 v3다.

## 실제 배정 방식

대시보드 버튼은 요청을 저장하고 [로컬 제작 총괄](local-production-worker.md)을 즉시 실행한다. 서버가 기존 로그인과 기본 모델로 `codex exec`를 시작하고, 총괄은 연결된 실제 서브에이전트 도구를 사용한다. 별도 유료 Agents API는 연결하지 않는다. 앱 예약의 5분 확인에 의존하지 않는다. 실제 런타임이 반환하는 canonical task ID 또는 UUID agent ID를 그대로 저장한다.

각 콘텐츠의 단계는 앞 결과에 의존하므로 순서를 지킨다. 모든 역할을 한꺼번에 실행하지 않는다. 현재 런타임의 동시 슬롯 안에서 현재 단계 담당자만 실행하고, 총괄은 그동안 실제 상태·중지 요청·입력 버전·다음 인계 자료를 점검한다. 독립 작업만 병렬화하며 아직 작성되지 않은 기획을 바탕으로 문안이나 영상을 시작하지 않는다.

Codex의 전문 서브에이전트 위임 개념은 [공식 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)를 참고하되, 실제 호출 메서드와 사용 가능한 슬롯은 현재 세션 도구 계약을 우선한다. 이 프로젝트는 별도 유료 Agents API를 새로 연결하지 않는다.

## 총괄 작업자 프로토콜

1. 기존 `worker-next`로 현재 단계를 가져오고 `job.input_json.specialist`를 읽는다. 실제 run의 페르소나·소재 조사·영상 지침·기획·이전 결과·체크포인트를 함께 준비한다. 공개 로그에는 소유권 토큰을 넣지 않는다.
2. 해당 역할을 수행할 **실제 서브에이전트**를 `collaboration.spawn_agent`로 만든다. 주는 메시지에 동결된 역할의 이름·전문성·지침·출력 계약, 이번 작업 입력과 허용 출력 경로를 명시한다. `fork_turns:"none"`으로 불필요한 개발 이력을 전달하지 않고 필요한 사실만 제공한다. 모델은 지정하지 않아 현재 기본값을 상속한다. 서브에이전트는 추가 에이전트를 만들지 않는다.
3. 생성 도구가 반환한 실제 agent ID/정식 task 이름을 저장한다. 역할명·가짜 UUID를 실제 ID처럼 만들지 않는다. 생성 직후에는 입력 확인과 작업 계획만 수행하도록 하고, 외부 검색·생성은 배정 저장과 총괄의 계속 가능 확인 후 시작한다. `worker-agent CYCLE TOKEN --agent-id 실제ID --role-id 역할ID`로 배정한다. 실패하면 생성한 에이전트에 중지를 알리고 외부 호출을 허용하지 않는다.
4. 배정 반환값의 `assignment_id`와 허용된 이번 작업을 `send_message` 또는 완료된 준비 작업의 `followup_task`로 전달한다. 역할 지침과 `docs/overnight-runbook.md`의 승인·비용·복구 원칙을 지킨다. 각 에이전트는 `output/content/<content_id>/specialists/<stage>/<assignment_id>/` 아래 새 결과 파일만 작성한다. 이전 입력이나 사람 수정본은 건드리지 않는다.
5. 총괄은 대기 중 주기적으로 `worker-ping`과 실제 중지 상태를 확인한다. 서브에이전트가 외부 검색·이미지 호출을 요청하면 호출 직전에 다시 `worker-ping`을 확인해 허용 범위를 전달한다. 중지·종료·일시정지면 에이전트에 새 호출 중지를 알리고 이미 반환된 결과만 보존한다. 60초를 넘는 차단 대기를 피한다. 변화 없는 확인을 사용자 대화에 반복 보고하지 않는다.
6. 에이전트의 실제 결과 파일과 완료 메시지를 읽는다. `specialist_assignment_id`를 해당 배정 ID로, `decision_summary`를 짧은 인계 요약으로 연결한다. 결과 파일은 `result_artifact`로 남긴다. 맡긴 역할의 이름만 달아 총괄이 대신 작성한 결과를 서브에이전트 산출물로 기록하지 않는다.
7. sources는 리서처의 조사 파일을 총괄이 `worker-sources`로 등록한 뒤 반환된 `research_id/source_ids`와 배정 ID로 완료한다. 이미 등록된 조사 기록은 복구해 재사용한다. planning·storyboard·copy는 실제 결과로 완료한다. images의 이미지 파일은 실재 여부를 확인해 완료하고, 영상이면 비주얼 담당자의 제안을 확인한 뒤 **총괄만** `worker-video`를 호출한다. 같은 영상 요청을 두 번 보내지 않는다. 비동기 완료도 최초 전문 담당 배정에 연결된다.
8. quality는 제작 담당자와 다른 실제 에이전트로 배정한다. `passed:false`면 완료 처리하지 말고 `worker-repair`로 지정된 단계만 재작업한다. register는 패키징 담당자의 manifest를 총괄이 import하고 반환된 정확한 content_id/version으로 완료한다. 승인 API와 SNS 게시를 이 제작 위임에 포함하지 않는다.
9. 실제 결과와 배정 기록을 저장한 후 다음 단계를 가져온다. 단일 담당자가 여러 분야를 같은 컨텍스트에서 대신 수행하지 않도록 역할별 에이전트를 구분한다. 동일 역할을 재사용할 때에도 현재 작업 입력을 새로 전달한다. 재시작 시 저장된 agent ID가 현재 런타임에 살아 있는지 확인하고 외부 결과·체크포인트부터 복구한다. 사라진 에이전트나 불확실한 생성은 완료했다고 표시하거나 무조건 재호출하지 않는다.

서브에이전트 도구를 사용할 수 없거나 슬롯이 없으면 배정을 꾸며내지 않는다. 실제 실패·대기를 로그에 남기고 기존 재시도/확인 필요 경로를 따른다. 개발용 에이전트의 이름을 실제 콘텐츠 제작 기록에 넣어 구현만으로 운영이 수행된 것처럼 표시하지 않는다.

## 대시보드와 복구

- 전문가 팀은 `/api/state`의 `specialists.cycle`, `stage_jobs`, 실제 `assignments/current`를 기준으로 갱신한다. 상세 산출물 파일 조회가 늦거나 실패해도 팀 상태는 먼저 표시한다. 입력창 포커스·MD 등록 중에는 전체 화면 재생성을 피하면서 팀 패널만 갱신한다.
- 5초 주기의 최근 확인 시각을 표시하고, 실행 접수만 된 상태·작업자 연결 지연·전문가 배정 대기·작업 중·완료·중단을 구분한다. 배정 기록 없이 전문가가 실행 중이라고 표시하지 않는다. 단계 인계 중 소유권이 없어도 같은 순환의 완료 기록은 유지하며 새 순환이나 재작업에는 이전 완료 표시를 사용하지 않는다.
- AI 자동 제작의 단계마다 설정된 전문가 역할과 실제 배정 여부를 구분해 표시한다. 역할 구성이 존재해도 agent가 실행되었다고 표시하지 않는다.
- 단계 상세에 담당 역할·실제 agent ID·시도·인계 요약을 표시하고 원본 결과 파일·JSON·이벤트 로그를 보존한다.
- 재시도·수정 요청·중지 시 배정 이력도 함께 남긴다. 예전 시도의 늦은 결과로 최신 단계를 완료할 수 없다.
- DB의 역할/배정 검증은 코디네이터가 실제 런타임 ID를 보고했다는 기록이다. HTTP 서버가 Codex 내부 런타임의 존재를 독립 인증한다는 의미는 아니다.

## 실행별 목표 개수

제작 총괄은 `run.settings.stop_after_posts`와 `completed_count`를 따른다. null은 개수 제한 없음이며, 정수는 성공적으로 피드 등록한 콘텐츠 수의 목표다. 승인 여부·카드 장수·영상 파일 수는 세지 않는다. 목표 도달 또는 종료 시각이면 서버가 실행을 완료한다. `worker-next.should_work:false`에서 새 위임이나 외부 호출을 시작하지 않고 완료 run을 임의로 새로 만들지 않는다. 각 전문가가 자체적으로 콘텐츠 개수를 늘리거나 목표를 바꾸지 않는다.

## 이야기 설계 보강 — 역할 묶음 v4

[Instagram 표본 조사와 제작 지침](storyboard/README.md)을 연결했다. 스토리보드 역할의 `playbook`에는 MD의 경로·버전·SHA-256과 **본문 전체**가 들어 있다. 새 run에서 기존 역할 동결 로직이 이 본문도 저장하므로 총괄은 `job.input_json.specialist.playbook`을 담당자에게 빠뜨리지 않고 전달한다. 이후 파일 수정이나 재시작으로 진행 중 run의 지침을 바꾸지 않는다.

기획자는 `story_premise`, 디렉터는 `story_design`과 `engagement_review`, 검수자는 `story_checks`를 작성한다. 영상 디렉터는 도입 후보·선택, 시간표·새 정보·상태 변화, `video_prompt`·`video_narration`을 함께 넘긴다. 생성 전 점검에서 도입 기대와 결과가 연결되지 않거나 무의미한 반복 구간이 있으면 총괄이 해당 단계의 수정을 먼저 요청한다. 실제 영상 검수에서는 제작자의 자기 평가를 대신 사용하지 않는다.

이는 에이전트의 작업·인계 계약이다. 서버의 최소 JSON 검증이 모든 창작 항목이나 재미를 자동 판정하는 것은 아니다. 기존 역할 묶음으로 시작한 실행에 새 필드를 소급 강제하지 않는다. `video_guides`의 낮은 관여도와 기존 비용·재시도·승인 정책은 유지한다. 실제 영상 요청이 `video_prompt`를 우선 사용하므로 핵심 연출을 cards나 보조 MD에만 남기지 않는다.
