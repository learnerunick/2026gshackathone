# 자동 제작 연속 실행 점검

## 동작과 이번 보완

새 실행은 `ai_quality_review_enabled:false`가 기본이며 소재 → 기획 → 스토리보드 → 문안 → 미디어 → 피드 등록을 반복한다. 피드의 사람 승인 대기는 다음 콘텐츠 시작 조건에 포함하지 않는다. 실행 관리자는 한 콘텐츠를 마친 작업자가 종료하면 다음 작업자를 실행한다. 종료 시각과 목표 개수를 비우면 별도의 오전 9시 종료 조건은 없다.

영상 오류가 복구돼도 run이 blocked로 남아 별도 재개가 필요했던 경로를 수정했다. 현재 콘텐츠·현재 전문가 배정·현재 요청 키에 연결된 동일 외부 영상 작업의 완료와 파일을 확인하면, 단계 완료와 해당 영상의 차단 해제를 한 트랜잭션으로 저장한다. 실제 공급자 실패가 확인된 기존 작업은 실패로 보존하고 다음 콘텐츠로 진행한다. 이 경우에도 세 콘텐츠 연속 실패 제한은 유지한다. 복구 사건은 `run.video_resolved`로 상세 로그에 남긴다.

확인하지 않은 결과를 성공 또는 실패로 추측하지 않는다. 다른 콘텐츠의 영상이나 이전 재생성 시도의 늦은 결과는 차단 해제 근거가 될 수 없다. 실제 파일과 결과는 재사용하며 유료 생성 요청을 복구 목적으로 재제출하지 않는다.

## 계속 진행하는 경우와 대기하는 경우

| 상황 | 동작 |
|---|---|
| 미디어 완료 | AI 품질 검수를 건너뛰고 피드 등록 |
| 피드 등록·사람 승인 대기 | 다음 이야기 시작 |
| 일시적인 업로드·조회·다운로드 오류 | 저장된 재시도 시각에 제한 횟수 내 복구 |
| 차단됐던 동일 영상의 완료 확인 | 사용자 재개를 추가 요구하지 않고 다음 단계 |
| 동일 영상의 생성 실패 확정 | 현재 콘텐츠 실패 보존 후 다음 이야기; 3회 연속 실패면 대기 |
| 목표 개수 또는 선택한 종료 시각 도달 | 종료 |
| 사용자의 일시정지·중지 | 그대로 유지 |
| 영상 예산·대기 한도 도달 | mixed는 이미지 전환, video_only는 대기 |
| 사용 한도·로그인·실행 환경 문제, 진전 없는 AI 종료 | 사유를 기록하고 확인 대기 |
| 유료 요청 접수 여부 불명·조회 복구 한도 초과 | 기존 작업 ID와 파일 보존, 확인 대기; 자동 재결제 없음 |
| 서버 또는 Mac 종료·절전·네트워크 단절 | 정상 실행을 보장할 수 없음; 저장 상태를 기준으로 복구 |

## 검증 범위

`tests/test_local_worker.py`에서 실제 로컬 실행 관리자와 테스트용 자식 프로세스로 콘텐츠 3건·18단계를 연속 완료하고 모두 사람 승인 대기로 남는 것을 검증했다. `tests/test_continuity_review.py`는 영상 완료 복구, 확정 실패 후 다음 이야기, 중지·일시정지·다른 차단 유지, 미확인 실패 조작 거부와 중복 제출 방지를 검증한다. 기존 제한·복구·버전 보호 테스트도 함께 실행한다.

이 검증은 임시 DB와 영상 공급자 대역을 사용한다. 실제 모델의 밤샘 연속 생성이나 외부 서비스 무중단 운영을 증명하는 테스트는 아니며 유료 API 호출·SNS 게시를 수행하지 않는다. 점검 당시 실제 실행은 사용자 중지 상태였고 이를 재개하지 않았다.
