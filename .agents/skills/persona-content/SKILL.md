# Persona Content

사용자가 정한 페르소나를 유지하면서 공감, 일상의 공유, 취향 발견을 중심으로 콘텐츠를 만든다. 브랜드·상품은 그 일상에 등장할 이유가 있어야 한다. 운영 속도보다 이야기의 매력과 캐릭터 일관성을 우선한다.

## 프로젝트 기준 확인

- 먼저 [프로젝트 인계 문서](../../../PROJECT_HANDOFF.md)를 읽고, 현재 요청과 후속 결정으로 갱신된 내용을 우선한다. 문서의 과거 마감일을 미래 작업의 마감일로 재사용하지 않는다.
- 프로젝트에 페르소나, 승인된 기준 이미지, 브랜드·상품 자료, 최근 게시물, 콘텐츠 스키마가 있으면 해당 작업에 필요한 자료를 읽는다. 직접 찾을 수 있는 사실을 사용자에게 다시 묻지 않는다.
- 확정된 사항, 제안, 미정 사항을 구분한다. 연령·성별·직업·이름·상품·SNS가 미정이면 임의로 확정하지 않는다. 초안이 가능하면 제안이라고 표시하고, 결과를 좌우하는 누락 사항만 질문한다.
- 현재 기준은 실사형 가상 인플루언서와 유동적인 카드 장수다. 약 5장은 참고 분량이며 목표·최소·최대 장수가 아니다. 이야기와 사용자가 정한 생성 한도에 따라 필요한 장수를 제안한다.

## 페르소나와 시각적 일관성

페르소나 자료에서 다음을 구분해 유지한다.

- 고정 기준: 인물 정체성, 얼굴 특징, 체형, 기본 성격, 말투, 생활 배경, 핵심 취향.
- 장면별 변화: 표정, 포즈, 상황에 맞는 의상, 장소, 조명. 이야기에서 의도한 변화만 적용한다.
- 이미지 역할: 인물 기준 이미지, 편집 대상 이미지, 상품 참고 이미지, 분위기 참고 이미지를 각각 식별한다.

새로운 이름이나 외형 특징을 기존 페르소나에 조용히 추가하지 않는다. 변경을 요청받으면 변경안을 기존 버전과 구분하고, 해당 콘텐츠에 사용한 페르소나·기준 이미지 버전을 기록한다.

실제 이미지 생성·편집을 요청받으면 사용 가능한 `imagegen` 스킬과 연결 도구를 따른다. 프롬프트에는 기준 이미지의 역할, 유지할 인물 특징, 바꿀 장면 요소를 분리해 적는다. 설치되어 있거나 접근 가능하다는 이유로 생성 API가 서비스 백엔드에 연결됐다고 가정하지 않는다.

기준 이미지와 결과를 직접 비교해 얼굴, 머리, 체형, 장면 간 연속성, 상품 표현을 확인한다. 결과를 보지 않았다면 시각적 일관성은 미검증으로 표시한다. 같은 프롬프트나 시드 사용만으로 동일 인물을 보장한다고 말하지 않는다.

## 이야기와 상품의 연결

1. 이번 게시물에서 공감할 상황이나 감정을 한 문장으로 정한다. 최근 콘텐츠와 상황·감정·상품·구도가 반복되는지 확인한다. 최근 이력이 없으면 중복 검사는 미검증이라고 남긴다.
2. 사용자가 지정한 상품이 있으면 그 상품이 필요한 일상 맥락을 찾는다. 지정 상품이 없으면 이야기와 취향에 맞는 후보를 검토한다. 브랜드를 넣기 위해 억지 사건을 만들지 않는다.
3. 장면마다 이야기에서 맡는 역할을 정하고, 반복되는 장면은 합치며 필요한 장면은 추가한다. 정해진 장수를 채우려고 장면을 늘리지 않는다.
4. 캐릭터의 관점으로 문안과 해시태그를 작성한다. 상품 설명이 대화의 흐름을 끊거나, 모든 장면이 광고 문구가 되지 않는지 검토한다.

작은 일상 상황 → 취향 탐색 → 어울리는 상품 소개 → 감정이나 대화의 마무리는 가능한 구성 예시다. 매번 같은 구조로 강제하지 않는다.

스토리보드를 작성할 때 현재 전문 역할 입력에 `playbook`이 있으면 그 동결 본문을 사용한다. 제작 기준과 조사 근거는 [스토리보드 자료](../../../docs/storyboard/README.md)에 있다. 관객의 궁금증, 페르소나의 선택, 장면마다 새로 보이는 정보, 마지막의 결과를 구체화한다. 외형 일관성을 모든 장면의 같은 구도·느린 동작·미소로 축소하지 않는다. 참고 계정의 실제 얼굴·이력·대본을 복제하지 않으며, 과거 run의 동결 지침을 최신 파일로 조용히 교체하지 않는다.

## 정보와 표현의 검수

- 상품 관련 주장마다 자료 출처와 확인일을 연결한다. 공개 자료와 가상 데이터를 구분한다.
- 기간이 있는 가격·혜택·행사 정보는 시작일·종료일 또는 유효 여부를 확인한다. 확인되지 않은 정보를 현재 사실처럼 쓰지 않는다. 출처 URL이나 날짜를 만들어내지 않는다.
- 이미지에 실제와 다른 포장, 로고, 상품명, 주요 기능이 표현되면 검수 문제로 표시한다. 상품 이미지의 역할과 변형 가능 범위를 생성 지시문에 명시한다.
- 가상 인물임을 게시 문안이나 해당 채널의 명확한 표시 방식으로 드러낸다.
- 인물이 실제로 특정 상품을 구매·사용했다는 체험담, 효능이나 만족도를 지어내지 않는다. 가상 인물 표시가 있다는 이유로 허구의 구매·사용 주장을 허용하지 않는다.
- 이미지 장수 제한과 별개로 현재 정해진 생성 횟수·비용 한도를 지킨다. 한도가 아직 없으면 임의의 운영 한도를 확정하지 않는다.

## 산출물과 수정

기존 API 계약이나 콘텐츠 스키마가 있으면 그 형식을 사용한다. 없으면 요청 범위에 맞춰 다음 항목을 Markdown으로 정리한다. 요청하지 않은 대규모 문서나 산출물은 만들지 않는다.

- 사용한 페르소나·콘텐츠 버전과 이번 이야기의 주제.
- 연결할 브랜드·상품, 연결 이유, 출처와 유효기간 확인 상태.
- 제안한 카드 장수와 순서. 각 카드의 이야기 역할, 화면 구성, 이미지 지시문, 필요한 문안.
- 게시 문안, 해시태그, 가상 인물 표시.
- 검수 결과: 이야기의 자연스러움, 캐릭터·말투 일관성, 상품 정보, 최근 주제 중복, 아직 검증하지 못한 항목.

사람이 작성·수정한 최신 내용을 기준으로 작업한다. 비동기 생성 결과는 시작 시점의 콘텐츠 버전에 연결된 제안으로 취급하고, 최신 수정본을 덮어쓰지 않는다. 파일로 저장할 때도 기존 수정본을 보존하고 변경안을 구분한다.

AI 검수 통과를 사람의 승인으로 간주하지 않는다. 승인된 콘텐츠를 수정하면 새 버전은 재승인 대상이라고 표시한다. 게시 실행과 상태 저장은 프로젝트의 백엔드 계약을 따르며, 이 스킬만으로 승인·게시·작업 복구가 구현됐다고 주장하지 않는다.

## 선택적인 영상

영상은 사용자가 요청한 범위에서 추가한다. 기존 이미지에 움직임·전환·자막을 붙이는 편집 영상과 인물의 움직임을 새로 합성하는 생성 영상을 구분한다.

Remotion으로 편집 영상을 만들 때는 사용 가능한 `remotion-best-practices`를 읽는다. 생성 영상에는 별도의 연결 도구가 필요하다. 도구·권한·실행 결과를 확인하기 전에 가능하다고 단정하지 않는다.

설치·기획·문안 작성 요청을 유료 생성이나 SNS 게시 요청으로 확대하지 않는다. 실제 실행은 현재 요청과 이미 주어진 승인 범위에 따른다.
